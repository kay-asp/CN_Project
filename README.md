# Reproduction of Sanders, Wilson & Gershman (2020)

Reproduction of "Hippocampal remapping as hidden state inference", *eLife* 9:e51140.

Reproduces Figure 2 (cue constellations, four features), Figure 3B and 3C
(experience-dependent remapping), Figure 7B (the early-vs-late morph
prediction) and Figure 9A (Figure 3C for three values of alpha), repeats them
over 200 seeds, and runs the sensitivity analyses quoted in the review
(Table 1 and the sigma sweep).

## Files

| File | Contents |
| --- | --- |
| `model.py` | The model, written from the paper's equations: CRP (Eq 4, 5), normal-Wishart marginal likelihood (Eq 2), Student-t posterior predictive (Eq 10), partition posterior (Eq 6), partition and state evidence ratios (Eq 7, Eq 11), probe assignment (Eq 8). Also the plotting functions used by the notebook. |
| `experiments.ipynb` | Tests of `model.py` (Eq 2 vs numerical integration, chained Eq 10 vs Eq 2, Eq 5 vs sequential Eq 4, normalisation, Eq 11 vs Eq 8), then every figure and number in the review. Saved with its outputs, so the results can be read without running it. |
| `compare_original.py` | Optional validation: compares this code's numbers with the authors' released code (see step 3). |
| `requirements.txt` | Packages for `model.py` and the notebook. |
| `requirements-original.txt` | 2020-era packages needed to run the authors' released code, used only by `compare_original.py`. |
| `figures/` | Figures written by the notebook. `axis_flip.png` and `repro_comparison.png` are the review's Appendix figures; they combine panels from the paper (CC BY 4.0) with this code's figures and are not regenerated by the notebook. |
| `results/` | CSV/JSON outputs behind every figure and number. |

## How to run

All commands are run from this folder.

### 1. Install

Any recent Python 3 (tested on 3.14):

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Run the notebook

```bash
jupyter notebook experiments.ipynb
```

Then choose *Kernel > Restart & Run All*. The test cells come first and raise an
error if a check fails. The whole notebook takes about 15 seconds. Set
`QUICK = True` in the first code cell for a faster run with fewer seeds.

To run it without opening a browser:

```bash
jupyter nbconvert --to notebook --execute --inplace experiments.ipynb
```

Outputs:

| Output | Contents |
| --- | --- |
| `figures/fig2_reproduction.png` | Fig 2 (state evidence ratio for four probes after 20 four-feature observations), with the 200-seed range |
| `figures/fig3b_reproduction.png` | Fig 3B (predictive densities after 10 pairs) |
| `figures/fig3c_reproduction.png` | Fig 3C (negative partition evidence ratio, with 200-seed band) |
| `figures/fig7_reproduction.png` | Fig 7B (morph evidence ratio, 5 vs 25 pairs, with 200-seed bands) |
| `figures/fig9a_reproduction.png` | Fig 9A (Fig 3C for alpha = 1, 1e-5, 1e-10) |
| `results/fig2_seed1.csv` | The Fig 2 values for seed 1, and the 200-seed median and 5-95% range |
| `results/sensitivity_table.csv` | The review's Table 1: seed-1 Fig 3 run with one setting changed; first pair favouring two states, and the evidence ratio after 15 pairs in the paper's sign (Fig 3C plots it reversed) |
| `results/seeds.csv` | Fig 3 switch point and whether the Fig 7B prediction holds, for each of 200 seeds |
| `results/sensitivity_sd.csv` | The same for each value of sigma |
| `results/summary.json` | Headline numbers quoted in the review |

If `results/comparison_original.json` is present (it is included), the released
code's values are drawn as crosses on the Fig 2, Fig 3C and Fig 7B plots.

### 3. Optional: validate against the authors' released code

This step is not needed to run the notebook. It checks that this
reimplementation gives the same numbers as the authors' code, and it is the
source of the agreement reported in the review. The authors' code is not
included here and none of it is copied; `compare_original.py` imports their
modules, unmodified, from a separate download.

a. Download the authors' code (MIT licence), commit 8accdd8:

```bash
git clone https://github.com/HoniSanders/Sanders-et-al-2020-Elife ../Sanders-et-al-2020-Elife
git -C ../Sanders-et-al-2020-Elife checkout 8accdd8
```

b. Their code fails on NumPy 2, so make a separate Python 3.8 environment:

```bash
python3.8 -m venv .venv-original
source .venv-original/bin/activate
pip install -r requirements-original.txt
```

c. Run the comparison, giving the path to their folder:

```bash
python compare_original.py ../Sanders-et-al-2020-Elife
```

It prints the largest differences for Fig 2, Fig 3C and Fig 7B and rewrites
`results/comparison_original.json`. For Fig 2 it drives the released `model.py`
with the settings of `nosinglecue.py`, which is not imported because it saves a
figure when imported. Re-run the notebook afterwards (in the main
environment) to redraw the crosses from the new file.

## Parameters

| Parameter | Value | Source |
| --- | --- | --- |
| alpha | 0.1 | paper, Methods |
| normal-Wishart prior | mu0 = 0, kappa0 = 0.001, nu0 = 0.02, T0 = 0.02 I | paper, Methods |
| context means, sd | -1 / +1, sd = 0.3 | paper, Fig 3 text (p. 7); also released code (`partitionParams.py`) |
| Fig 2 | 20 observations, four features from N(0, 0.2^2), seed 1; probes 0000, 1000, 1001, 1111 | paper, Fig 2 caption |
| Fig 3 | 15 pairs, seed 1 | released code |
| Fig 7B | 5 vs 25 training pairs, 11 probes from -1 to +1 | released code (`morph.py`) |

"Pairs": each training step shows one observation from each context, so
5 and 25 pairs are 10 and 50 observations. The original Fig 7B legend says
"5/25 Observations".

The seed-1 curves for Figs 3, 7B and 9A use the same random stream as the
released code (see `ORIGINAL_BURN_PER_PAIR` in `model.py`). Seed bands and
sweeps use clean streams for seeds 1..N.
